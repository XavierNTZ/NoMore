# Contributing to NoMore

[Présentation en français](README.fr.md) · [Roadmap](ROADMAP.md)

NoMore is in its documentation and planning stage. The open-source licence still needs to be selected; see [LICENSING.md](LICENSING.md). Do not assume that publication of this repository resolves contribution or reuse rights.

## Useful early contributions

Feedback is welcome on the requirements, accessibility, translation quality, privacy boundaries, support-resource selection and clarity of the documentation.

Before starting substantial code or submitting third-party material, open a non-sensitive issue to agree on scope and licensing. Feature requests should explain the user need, proposed behaviour and possible safety or privacy consequences.

## How to propose a change

Read the README and roadmap, check existing issues, then propose a focused change. A future pull request should explain what changes, why it is needed, what was tested and which limitations remain.

Do not invent test results or claim a feature is deployed merely because code has been generated. AI-assisted work requires the same review as other contributions, with careful checks for fabricated sources, insecure code and third-party material.

## Non-negotiable boundaries

- Never post personal consumption histories, medical documents, client records, credentials or real database exports.
- Use synthetic data for examples, screenshots and tests.
- Do not propose diagnosis, medication advice, automated withdrawal plans or personalised life-expectancy estimates.
- Do not add advertising trackers, session replay or gambling promotions to personal tracking areas.
- Do not submit material without the necessary rights or remove third-party licence notices.

## Language and conduct

English is the initial shared documentation language; French feedback is welcome. French, English and Spanish are the first planned application languages.

Be respectful, specific and non-stigmatising. Discuss behaviour and design choices without judging people or asking contributors to disclose lived experience.

For sensitive technical concerns, follow [SECURITY.md](SECURITY.md). Public issues are not a confidential channel or an emergency-support service.
